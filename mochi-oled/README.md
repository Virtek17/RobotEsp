# Mochi — программные эмоции KITIOT

## Текущий режим OLED: только лица

Текст полностью убран с экрана: IP, подписи состояний, ответы и ошибки не рисуются. Лица занимают весь экран и не чередуются со страницами текста. Эмоции ИИ, запись речи и озвучивание через ноутбук сохранены. Текст ответов и ошибок доступен в браузере, IP — в Serial Monitor. Изменение требует обычного Upload, без загрузки файловой системы. Описания текстового OLED ниже относятся к прежним версиям.

## Эмоции ИИ и состояния

В режиме диалога автоматическая реакция удивления на громкость по умолчанию выключена (`SOUND_REACTIONS_ENABLED=false` в input_config.h). Запись микрофона и эмоции от ИИ продолжают работать. Для прежней реакции на хлопки включите этот параметр. USB Serial настроен без ожидания передачи, чтобы диагностический вывод не тормозил HTTP и звук при закрытом Monitor. Открытие Monitor может перезапустить плату; зависимость от Monitor на реальной плате ещё требуется проверить холодным запуском без него.

Новая версия принимает вместе с текстом выбранную ИИ эмоцию из существующего списка 20 выражений. На OLED сначала показывается эмоциональное лицо, затем текст; во время озвучивания на ноутбуке лицо и текст чередуются. Состояния имеют подписи: «Слушаю», «Распознаю», «Думаю», «Отвечаю», «Говорю», «Ошибка», «Нет Wi-Fi». Для включения загрузите код обычным Upload; анимации файловой системы не нужны.

Озвучивание выполняет локальный сервер Windows через колонки/аудиовыход ноутбука, а не ESP32. Подключение кнопки, микрофона и OLED остаётся прежним. Новое касание прерывает голос на компьютере; удержание включает следующую запись. Для всех новых состояний нужен обновлённый сервер.

## Русская речь → текст на OLED

Короткое касание кнопки теперь переключает эмоцию при отпускании. Удержание дольше 350 мс включает запись с INMP441; говорите после «Слушаю», отпустите для распознавания. Лимит 4 секунды, при нехватке памяти — 2–3 секунды (лимит выводится в Monitor). Плата временно подавляет реакцию на громкость во время записи и показа текста. Удерживайте тишину при запуске для калибровки детектора громкости.

Распознавание выполняет запущенный на ПК `../mochi-control-server/server.js` с локальной русской моделью Vosk. Настройка описана в его README. Кириллица выводится на OLED, длинные фразы — страницами, затем возвращается лицо. Прошить обычным Upload; файловую систему обновлять не нужно.

## Кнопка и микрофон INMP441

Соединять при отключённом USB и другом питании. Если плата сильно нагревалась, сначала выясните причину; загрузка этой прошивки не устраняет аппаратную неисправность.

| Модуль | Контакт | ESP32-C3 SuperMini |
|---|---|---|
| OLED | GND / VDD | GND / 3,3 В |
| OLED | SDA / SCK | GPIO20 / GPIO21 |
| Сенсорная кнопка | GND / VCC | GND / 3,3 В |
| Сенсорная кнопка | I/O | GPIO3 |
| INMP441 | GND / VDD | GND / 3,3 В |
| INMP441 | L/R | GND (левый канал) |
| INMP441 | SD | GPIO4 |
| INMP441 | WS | GPIO5 |
| INMP441 | SCK | GPIO6 |

Не путайте SCK микрофона с SCK дисплея: это разные интерфейсы и разные GPIO. Микрофон питается от 3,3 В, не от 5 В. У INMP441 вывод WS, не RS. По документации INMP441 линия SD должна иметь подтяжку к земле 100 кОм; если её нет на модуле, добавьте внешний резистор SD–GND. В коде также включена внутренняя подтяжка SD к земле. Источник: https://invensense.tdk.com/wp-content/uploads/2015/02/INMP441.pdf

Поведение без компьютера и ИИ:

- Короткое касание переключает на следующую из 20 эмоций; удержание запускает запись речи. Предполагается сенсорный модуль с цифровым выходом HIGH при касании и режимом без фиксации. Для другого уровня поменяйте `TOUCH_ACTIVE_HIGH` в `src/input_config.h`.
- Громкий звук вызывает `surprised` на 1,5 секунды, затем возвращается выбранная эмоция. Повторная реакция возможна через 2,5 секунды. Новое касание или веб-команда отменяют текущую временную реакцию.
- После включения держите тишину первые 1,5 секунды для начальной оценки фонового шума. Это детектор громкости, а не распознавание речи или хлопков.
- Monitor, 115200: `Touch -> happy`, `Mic RMS: ... | trigger: ...`, `Sound -> surprised`. RMS — условные единицы сигнала, не децибелы. Постоянный ноль при звуке требует проверки проводки, питания, L/R и микрофона; успешная инициализация I2S сама по себе не подтверждает подключение микрофона.
- Диагностика микрофона раз в секунду: `L max` / `R max` — максимальная громкость коротких окон за интервал (чтобы не пропустить хлопок), `frames` — число прочитанных пар отсчётов за интервал, `nonzero L/R` — число ненулевых 24-битных отсчётов. `frames > 0` при нулях в обоих каналах означает, что I2S принимает нули; проверяйте питание и проводку. Сигнал только справа — проверьте соединение L/R с GND. Если отсчётов нет, выводится последняя ошибка чтения. Порог по-прежнему применяется к левому каналу.
- Чувствительность регулируется в `src/input_config.h`: меньше `MIC_MIN_TRIGGER_RMS` — чувствительнее, больше — менее чувствительно. `MIC_NOISE_MULTIPLIER` задаёт порог относительно фона. Для работы только с кнопкой установите `MICROPHONE_ENABLED = false`.

Загрузить обычным **Upload**, без **Upload Filesystem Image**. Сигнал микрофона постоянно обрабатывается для измерения громкости; при удержании кнопки фраза записывается в RAM и передаётся локальному серверу для распознавания, без облака и файлов аудио. Микрофон и кнопка проверены пользователем на прежней прошивке; новый режим записи и OLED-текста требует испытания на плате.

Текущая прошивка использует рисунки и анимацию из экспорта U8g2 сайта https://mochi.kitiot.com/ (получен 26.10.2026), персонаж Mochi. Перенесены все 20 выражений Mochi со страницы выбора: `alive`, `happy`, `love`, `angry`, `furious`, `sad`, `dizzy`, `sleepy`, `deep_sleep`, `confused`, `surprised`, `wink`, `cat`, `smiling`, `lol`, `smug`, `star_struck`, `cool`, `cheeky`, `derp`. Другие персонажи сайта не перенесены.

- Рендеринг: `src/kitiot_face.h`, примерно 30 кадров/с, моргание, плавные взгляды, зевки. Автоматическая смена эмоций отключена, выбор выполняется через прежний веб-интерфейс.
- Стартовая эмоция: `alive`. API и локальный сервер Node.js сохранены; список кнопок загружается с платы автоматически.
- Подключение прежнее: SDA GPIO20, SCL GPIO21, SSD1306 128×64, адрес 0x3C. Настройки Wi-Fi сохранены.
- Для установки выполните PlatformIO **Build**, затем **Upload**. **Upload Filesystem Image не требуется**: лица рисуются кодом без LittleFS.
- IP выводится в Serial Monitor (115200) каждые 5 секунд и на OLED на 10 секунд после подключения.
- Полный экспорт сохранён в `../mochi-source/kitiot-all-export.ino`, скрипт повторного импорта — `../mochi-source/import-kitiot.cjs`; предыдущая прошивка — в `../mochi-source/main-littlefs-backup.cpp`. Старые `.mch` и GIF сохранены для возврата, но текущая прошивка их не использует.

# The Mochi: ESP32-C3 Super Mini + OLED 128×64

Готовый проект PlatformIO. В `data/` находятся 18 эмоций из открытого репозитория автора. Это не все 80+ эмоций прошивки The Mochi v4.3.2: остальные исходники автор не опубликовал в найденном репозитории.

## Подключение

В примере используются контакты из схемы The Mochi: VCC → 3.3V, GND → GND, SDA → GPIO20, SCL → GPIO21. Если у вас работающая схема использует другие GPIO, поменяйте `OLED_SDA` и `OLED_SCL` в `src/main.cpp`. Для OLED 0,96 дюйма принят контроллер SSD1306 и адрес I²C `0x3C`. Жёлтая и голубая зоны экрана — физические полосы дисплея; отдельная настройка цвета не нужна.

## Загрузка через VS Code + PlatformIO

1. Установите VS Code и расширение **PlatformIO IDE**. Дождитесь завершения его установки.
2. Откройте через **File → Open Folder** именно папку `E:\Projects\ESP32\mochi-oled` — в ней лежит `platformio.ini`. Не создавайте ещё один проект поверх неё.
3. Подключите ESP32-C3 кабелем USB с передачей данных. В диспетчере устройств Windows найдите её COM-порт.
4. В `src/main.cpp` проверьте SDA, SCL и адрес OLED. В `src/wifi_config.h` впишите имя и пароль вашего домашнего Wi-Fi 2,4 ГГц. ПК может оставаться на своём обычном подключении.
5. Внизу VS Code выберите **PlatformIO: Build** (галочка) и дождитесь `SUCCESS`.
6. Выполните **PlatformIO: Upload** (стрелка). Эта операция заменит прежнюю прошивку The Mochi. Если подключение не начинается, удерживайте **BOOT**, кратко нажмите **RST**, отпустите **BOOT** после начала загрузки и повторите Upload.
7. При первой установке загрузите анимации отдельно: **PlatformIO → Project Tasks → esp32-c3-supermini → Platform → Upload Filesystem Image**. Обычный Upload прошивает только код. Если файлы уже загружены и работают, при последующих изменениях `src/main.cpp` этот шаг повторять не нужно.
8. Нажмите **RST**. После подключения платы к домашнему Wi-Fi её IP-адрес будет показан на OLED на 10 секунд. Запишите его. Затем начнёт повторяться эмоция `content`.

Если PlatformIO выбрал не тот COM-порт, добавьте в `platformio.ini` строку `upload_port = COMx`, заменив `COMx` на ваш порт. Если на OLED появится `LittleFS not found`, проверьте, завершился ли шаг 7 с `SUCCESS`. Код должен монтировать раздел с именем `storage`, как указано в `partitions.csv`.

## Веб управление и своя логика

Отдельный веб сервер на Node.js лежит в соседней папке `../mochi-control-server`. ПК остаётся подключённым к своей обычной сети. ESP32 подключается к той же локальной сети, а Node.js отправляет ей команды по IP-адресу. Настройка и запуск описаны в README того проекта. Файл анимаций на плате уже загружен, поэтому при этой смене прошивки задачу **Upload Filesystem Image** повторять не требуется.

API платы: `GET /api/emotions` возвращает список и текущую эмоцию; `POST /api/emotion` с полем формы `emotion=happy` выбирает эмоцию. Список задаётся массивом `emotionNames`, а стартовая эмоция — `currentEmotion`. `updateEmotion()` вызывается из `loop()` без длинных `delay()`. Имена файлов в `data/` — допустимые имена эмоций без расширения `.mch`.

Если экран пустой, проверьте сначала питание и четыре провода, потом адрес I²C (`0x3C` или `0x3D`) и контроллер дисплея. Прошивку на реальной плате мы здесь ещё не проверяли.

## Формат данных

`convert.py` преобразует оригинальные GIF из `../mochi-source/some gif (not enough)/` в монохромные кадры 128×64. Кадры обрезаются по центру под пропорцию 2:1, масштабируются, порогово преобразуются и сжимаются PackBits. Формат `MCH1`: сигнатура, ширина, высота, число кадров (все `uint16_t`, little-endian), затем задержка и длина закодированного кадра (`uint16_t`) и данные кадра. Весь набор занимает 264711 байт. Все 1383 кадра проверены обратным декодированием.

Репозиторий автора указывает, что права на исходные изображения принадлежат создателю Dasai Mochi. Проверьте права перед распространением ресурсов.
