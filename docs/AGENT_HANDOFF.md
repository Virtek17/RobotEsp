# Контекст для нового агента: робот Мочи

Актуально на 1 ноября 2026 года. Прочитай этот файл, затем проверь текущий код: он важнее устаревших разделов README. Общайся с пользователем по-русски.

## Цель и последний запрос

Финальная цель — настольный робот с голосовым общением с ИИ, голосовыми ответами и эмоциями по контексту. Сейчас прототип работает через компьютер: ESP32 записывает микрофон и рисует лицо, ПК распознаёт речь, получает ответ ИИ и воспроизводит его через свои колонки.

Пользователь переходит на другой компьютер. Последнее обсуждение — ускорение и возможность локального ИИ. Локальную LLM пока НЕ устанавливали и НЕ подключали. Не считай обсуждение согласием на скачивание больших моделей. Сначала выясни характеристики нового ПК и сравни варианты. На старом ПК: i5-10210U, 8 ГБ RAM, Intel UHD. Обсуждали пробу Qwen3 1.7B через Ollama с отключёнными рассуждениями, но это лишь предложение.

## Предпочтения пользователя

- Не запускать и не перезапускать сервер автоматически: пользователь просил останавливать его и запускает сам. После изменений кода напомни о ручном перезапуске.
- На OLED никакого текста: только лица и эмоции. Не возвращай IP, расшифровку, ответы и подписи состояний на экран.
- Облачный ИИ только бесплатный. Не включать платные модели и платные fallback.
- Характер Мочи: свой дружбан, интернет-тролль, ирония, подколы, частый русский мат без цензуры. Текущий system prompt просит 1–2 матерных слова в большинстве обычных реплик, но полезные ответы по делу и поддержку без издёвок в серьёзных ситуациях. Это пожелание пользователя, не ошибка промпта.
- Секреты не выводить в чат, логи, браузер, прошивку или Git. Не читать целиком .env в вывод инструментов.

## Папки

## Подключение

Плата ESP32-C3 Super Mini, питание модулей 3,3 В, земля общая.

| Модуль | Вывод | Подключение |
|---|---|---|
| OLED SSD1306 128×64, адрес 0x3C | SDA | GPIO20 |
| OLED | SCK/SCL | GPIO21 |
| OLED | VDD / GND | 3,3 В / GND |
| Сенсорная кнопка, активный HIGH | I/O | GPIO3 |
| Кнопка | VCC / GND | 3,3 В / GND |
| INMP441 I2S | SD | GPIO4 |
| INMP441 | WS | GPIO5 |
| INMP441 | SCK | GPIO6 |
| INMP441 | L/R | GND, левый канал |
| INMP441 | VDD / GND | 3,3 В / GND |

Изначально микрофон давал сплошные нули; после работы с соединениями/пайкой заработал. Нули справа при работающем левом канале нормальны. Ранее пользователь сообщал сильный нагрев платы; устранение документально не подтверждено. При повторном нагреве сначала отключить питание и проверить монтаж.

## Как работает

1. Короткое касание переключает одну из 20 эмоций KITIOT/Mochi.
2. Удержание более 350 мс начинает запись, отпускание завершает. Максимум 4 с, при нехватке памяти возможен лимит 3 или 2 с.
3. PCM 16 кГц, моно, 16 бит хранится в RAM платы. Сервер опрашивает плату примерно каждые 150 мс, скачивает WAV.
4. Постоянный Python worker распознаёт русскую речь локально через Vosk; модель и декодер переиспользуются, между фразами Reset.
5. OpenRouter возвращает короткую реплику и emotion. История — последние 3 пары сообщений в памяти сервера.
6. Результат и эмоция доставляются плате. После успешной доставки сервер озвучивает ответ через Fish Audio/колонки ПК. Повторная доставка не должна заново вызывать STT, ИИ или озвучку.
7. Новое касание/запись отменяет текущую озвучку. Состояния отражаются лицом, без надписей.

Реакция удивлением на окружающий звук отключена по умолчанию (SOUND_REACTIONS_ENABLED=false): раньше лицо постоянно переключалось. Микрофон при этом работает для записи.

## Файлы реализации

- mochi-oled/src/speech.h — запись, состояния и HTTP API STT.
- mochi-oled/src/kitiot_face.h — рисование 20 лиц.
- mochi-oled/src/input_config.h — входы и звуковые реакции.
- mochi-oled/src/wifi_config.h — локальные настройки Wi-Fi, не публиковать пароль.
- mochi-control-server/server.js — HTTP на 127.0.0.1:3000, координация компонентов.
- speech.js — мост ESP32 → Vosk → ИИ → ESP32 → голос, тайминги и отмена.
- ai.js — OpenRouter, system prompt, история, проверка/очистка ответа.
- fish_voice.js — Fish TTS, выбор провайдера, нормализация WAV, отмена и диагностика сети.
- voice.js и speak.ps1 — локальный Windows System.Speech TTS.
- play_wav.ps1 — Windows SoundPlayer для Fish WAV из памяти.

## Настройка на новом Windows ПК

1. Перенести весь исходный проект. .venv и .pio лучше пересоздать; они не переносимая установка. Модель Vosk можно скопировать отдельно.
2. Установить Node.js поддерживаемой LTS-ветки (package.json допускает >=18), Python и VS Code с расширением PlatformIO IDE, если нужна прошивка.
3. В mochi-control-server создать окружение:

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements-stt.txt
   ```

4. Должен существовать models/vosk-model-small-ru-0.22/am. Если модели нет, скачать и распаковать https://alphacephei.com/vosk/models/vosk-model-small-ru-0.22.zip в models/. При нестандартном Python проверить MOCHI_PYTHON.
5. Перенести .env приватно либо заполнить по .env.example. Он и модели могут отсутствовать в Git! Нужны OPENROUTER_API_KEY, OPENROUTER_MODEL=openrouter/free, FISH_AUDIO_API_KEY и FISH_AUDIO_VOICE_ID. Переменные окружения имеют приоритет; значения из файла перечитываются на запросах.
6. ID голоса Fish — 32 hex-символа из ссылки /m/<id>/. Изначально выбран «Жириновский» от Dr Seedon: bc8eb8dcdc184763b0a769ee03275724. Пользователь затем выбирал другие голоса; фактический текущий ID проверять локально, не перезаписывать без причины.
7. ПК и плата должны быть доступны друг другу в LAN. Последний IP платы 192.168.0.100, записан в config.json; после смены сети он может измениться. Wi-Fi платы — 2,4 ГГц. IP теперь только в Serial Monitor, не на OLED.
8. Пользователь запускает в mochi-control-server: npm start или node server.js. Внешних npm-зависимостей у сервера нет. Интерфейс http://localhost:3000/.
9. Node сам обращается к плате, входящий доступ к ПК с платы не нужен. Проверить устройства вывода звука Windows; PowerShell-плеер Windows-специфичный. На другой ОС понадобится заменить воспроизведение.
10. При необходимости прошивки открыть папку mochi-oled в PlatformIO, Build/Upload. Monitor 115200. board=esp32-c3-devkitm-1; USB CDC включён. Файловую систему для лиц загружать не требуется. Не загружать прошивку автоматически без необходимости.

## API и диагностика

На ПК:
- GET /api/stt — состояние STT, ответ, эмоция, aiError, voiceError, тайминги, конфигурация AI/voice без ключей.
- POST /api/voice — enabled / stop.
- POST /api/ai/reset — очистка истории.

На ESP32:
- GET /api/stt/state — phase, id, samples, touch.
- GET /api/stt/audio?id=... — запись WAV.
- POST /api/stt/progress — id и stage (recognizing/thinking/speaking/answered).
- POST /api/stt/result — id/text/emotion/error.

Сверять параметры с кодом перед ручными запросами. Аудио хранится в памяти. Для STT оно локально; при Fish текст ответа уходит в облако и приходит синтезированное аудио.

STT timing включает downloadMs, recognizeMs, aiMs, deliveryMs, totalMs, но НЕ Fish TTS и воспроизведение. Для них отдельные Voice: starting / finished or stopped / Voice error. Один замер пользователя: download178мс, STT879мс, ИИ10262мс, доставка174мс, сумма11493мс. Основные кандидаты на ускорение — LLM и TTS, не Vosk.

## Недавние исправления и ограничения

- OLED полностью без текста; старые разделы README про IP на экране, «Слушаю», расшифровки и страницы устарели.
- Пользователь однажды сообщил, что заработало после открытия Monitor. Добавлен Serial.setTxTimeoutMs(0), чтобы USB Serial не блокировал работу; точная первопричина не доказана.
- Fish возвращал streaming WAV с огромными служебными размерами RIFF/data. Windows не проигрывал. normalizeWav пересобирает конечный PCM16 mono WAV с фактическими размерами без изменения отсчётов. Живое воспроизведение после исправления завершилось успешно.
- Fish запрос POST https://api.fish.audio/v1/tts с обязательным model: s2.1-pro-free. Не убирать заголовок: это может выбрать платный режим по умолчанию. WAV 24кГц, language ru, reference_id. Ошибки 401/402/429 различаются, платного fallback нет. Без Fish key+ID используется Windows TTS, но ошибка настроенного Fish не подменяется другим голосом молча.
- Voice error: fetch failed — сетевой сбой. Добавлена безопасная расшифровка DNS/reset/socket/timeout/TLS без вывода ключей и сырых ответов. Последующий отдельный запрос успешно получил WAV. Постоянная причина сбоя не установлена.
- OpenRouter HTTP400 ошибочно назывался «бесплатная модель недоступна». Проверка встретила ошибку с упоминанием reasoning, другая попытка прошла. Убран reasoning.enabled=false, оставлен reasoning.exclude=true; причинность не окончательно доказана. Теперь HTTP400 отдельно сообщает об отклонении параметров.
- Пустые/оборванные ответы подтверждены живой проверкой: выбранная через openrouter/free xingchen-agi/xing4.0-29b-a4b:free закончила finish_reason=length, 512 completion tokens и 512 reasoning tokens.
- Последнее изменение ai.js: первая попытка max_tokens2048, одна повторная попытка при непригодной реплике max_tokens4096, обе используют общий AbortSignal.timeout(20000). При content_filter/refusal повтор не делается; HTTP-ошибки также не повторяются. Успешный ответ только после проверки записывается в историю. Не выдавать внутренние reasoning как реплику!
- После этого живой запрос вернул готовый ответ, 8 AI-тестов прошли. Это не гарантия стабильности всех случайно выбранных бесплатных моделей. Большой бюджет может увеличить задержку, общий тайм-аут остаётся 20с.
- parseReply принимает JSON {text,emotion}, проверяет whitelist, для простого текста использует alive. cleanAnswer отсекает рассуждения/незавершённую генерацию и ограничивает реплику 220 символами.

## Проверки и дальнейшая работа

Из mochi-control-server:

```powershell
node --test ai.test.js fish_voice.test.js voice.test.js speech.test.js
```

speech.test.js требует установленный Vosk и модель. Последние отдельные проверки: AI 8/8, Fish 4/4; полный набор после самых последних изменений вместе ещё не прогоняли. Для простой правки промпта проверяли node --check ai.js.

Первоочередное на новом ПК: зависимости, модель Vosk, приватные настройки, доступность ESP32 и вывод звука. Затем снять отдельные тайминги ИИ и Fish. Возможные улучшения обсуждали, но НЕ реализовали: конкретная быстрая бесплатная модель вместо случайного роутера, локальная LLM, потоковый OpenRouter, TTS первого предложения и потоковое воспроизведение Fish. Не обещать ускорение локального ИИ до измерений на новом железе. Сохранять эмоции, отмену по кнопке, бесплатный режим и отсутствие повторной озвучки при доставочных ретраях.
