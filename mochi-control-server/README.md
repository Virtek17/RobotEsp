# Mochi Control Server

## Fish Audio — голос из каталога

WAV Fish Audio может иметь служебные размеры RIFF/data для потокового ответа. После полного получения аудио сервер формирует корректный конечный PCM WAV с фактической длиной, не меняя отсчёты. Это требуется плееру Windows. Журнал `STT timing` не включает синтез и воспроизведение; для них выводятся отдельные строки `Voice: starting`, `Voice: finished or stopped` и `Voice error`.

Подготовлен голос «Жириновский» от Dr Seedon, выбранный в редакторе пользователя: https://fish.audio/m/bc8eb8dcdc184763b0a769ee03275724/ . Его `reference_id` записан в `.env` как `FISH_AUDIO_VOICE_ID`. Вставьте отдельный API-ключ Fish Audio в `FISH_AUDIO_API_KEY`. Не используйте ключ OpenRouter и не отправляйте ключи в чат. После обновления серверного кода перезапустите сервер; дальнейшие изменения ключа/ID перечитываются автоматически.

Пока ключ Fish не задан, работает Windows. После добавления ключа и ID используется Fish Audio. Отправляется только текст ответа робота; исходная запись микрофона и ключ OpenRouter не передаются. Временный WAV воспроизводится в памяти через аудиовыход Windows и не сохраняется в файл. Если Fish выбран и вернул ошибку, другой платный маршрут и другой голос молча не включаются.

Запросы используют фиксированный HTTP-заголовок `model: s2.1-pro-free`. Это важно: по официальной документации отсутствие/ошибка в заголовке может выбрать платную модель. Платный заголовок не конфигурируется; при HTTP 402 выводится ошибка, без повторного запроса к платной модели. Бесплатность и доступность для аккаунта следует сверять с текущими условиями Fish Audio, никаких покупок код не совершает. Живой синтез требует ключа и ещё не проверен.

Документация: https://docs.fish.audio/api-reference/endpoint/openapi-v1/text-to-speech ; цены: https://docs.fish.audio/developer-guide/models-pricing/pricing-and-rate-limits . Ключи остаются в `.env` на ПК, прошивка не меняется. Проверки без ключа: `node --test fish_voice.test.js voice.test.js ai.test.js`.

Текущая прошивка OLED показывает только лица и анимации: текст, IP и подписи состояний убраны по запросу пользователя. Расшифровка и ответы остаются в браузере, озвучивание — через ноутбук. Указания о текстовых страницах на OLED ниже относятся к предыдущему режиму.

## Эмоции, состояния и голос ноутбука

ИИ возвращает один JSON-ответ с `text` и `emotion` (из 20 имён прошивки). Имя эмоции проверяется по белому списку; неизвестное заменяется на `alive`. Старые модели, вернувшие обычный текст, тоже поддерживаются с нейтральной эмоцией. Платные модели по-прежнему запрещены. Выбранная эмоция показывается на OLED и сохраняется до ручного выбора или следующей реакции.

Новая прошивка отображает лица с подписями «Слушаю», «Распознаю», «Думаю», «Отвечаю», «Говорю», «Ошибка» и «Нет Wi-Fi». Во время ответа лицо чередуется с текстом, чтобы одновременно видеть эмоцию и читать реплику. Для этого требуется **Upload из mochi-oled**, без Upload Filesystem Image. Старые версии прошивки могут показать текст, но не новые состояния.

Ответ озвучивает установленный русский голос Windows (на этом ПК найден Microsoft Irina Desktop) через аудиоустройство Windows по умолчанию. Браузер можно закрыть: звук воспроизводит сервер. Текст в TTS передаётся как данные, не как код; сторонний облачный синтез не используется. Подключённые наушники/Bluetooth могут стать аудиовыходом вместо колонок — выберите нужное устройство в Windows.

В веб-интерфейсе есть переключатель голоса и кнопка остановки. Голос включён по умолчанию при старте сервера; настройка действует до перезапуска. Новое касание кнопки робота прерывает текущую озвучку, чтобы не записывать собственный ответ. При ошибке голоса текст продолжает работать. Успешно доставленный ответ озвучивается один раз; повторная доставка после сетевого сбоя не повторяет голос. Контекст можно сбросить кнопкой нового разговора.

Проверка установленного русского голоса без звука: `powershell.exe -NoProfile -File speak.ps1 -Probe`. Тесты: `node --test ai.test.js speech.test.js voice.test.js`. При отсутствии русского голоса установите его средствами Windows; другой голос не подставляется молча.

## Ответы ИИ через OpenRouter (только бесплатные модели)

Заполните `OPENROUTER_API_KEY=` в локальном `.env`. Не публикуйте ключ и не добавляйте его в прошивку. `.env` исключён через `.gitignore`, браузеру и ESP32 ключ не передаётся. Сервер перечитывает файл при обращении, поэтому после добавления ключа перезапуск не нужен. Переменные окружения имеют приоритет над файлом.

Модель по умолчанию: `openrouter/free`. Разрешается также конкретный идентификатор с окончанием `:free`. Код отклоняет прочие модели до отправки запроса, платных fallback-моделей нет. Бесплатные квоты и доступность зависят от аккаунта и провайдеров; при исчерпании квоты на OLED появится сообщение об ошибке. Никакого автоматического пополнения или перехода на платную модель нет. Документация: https://openrouter.ai/docs/guides/routing/routers/free-router.

После подключения ключа: удержание кнопки → локальное распознавание → текст фразы в OpenRouter → короткий русский ответ на OLED. В браузере отдельно видны ваша фраза и ответ Мочи. В OpenRouter и выбранному им провайдеру передаются текст текущей фразы, инструкция персонажа и до трёх последних обменов; аудио остаётся на компьютере. Диалог хранится только в RAM сервера. Кнопка «Начать новый разговор» очищает контекст. При смене ключа история очищается.

Первый этап — текстовые ответы; озвучивание не добавлено. Прошивка с предыдущим speech-to-text уже совместима, повторный Upload для подключения OpenRouter не нужен. Максимальное ожидание облачного ответа — 20 секунд, затем показывается ошибка. Если ключ не задан, сохраняется прежний режим показа распознанной фразы.

Проверки ИИ без настоящего ключа и сетевых запросов: `node --test ai.test.js speech.test.js`. Живой ответ требует заполненного `.env` и проверки сети/квоты.

API запрашивает отключение и исключение reasoning; обработчик использует только message.content, удаляет завершённые блоки think/analysis/reasoning и отклоняет обнаруженный служебный анализ, пустые и оборванные по лимиту ответы. Невалидные ответы не включаются в историю. Готовая реплика ограничивается 220 символами. Эти проверки не гарантируют качество всех ответов случайной бесплатной модели. Актуальная погода, новости и веб-поиск к роботу пока не подключены — наличие облачного API не даёт модели доступ к погоде.

## Речь в текст на OLED (локально, русский язык)

На этом компьютере уже подготовлены `.venv` с Vosk и модель `models/vosk-model-small-ru-0.22`. Запуск прежний: `node server.js`. Веб-интерфейс: http://localhost:3000/. После изменения кода перезапустите сервер. Требуется новая прошивка из `../mochi-oled`, загрузка обычным Upload.

1. Дождитесь в веб-интерфейсе состояния готовности (русская модель загружается при запуске).
2. Короткое касание кнопки робота меняет эмоцию, удержание более 350 мс начинает запись. Начинайте говорить после надписи «Слушаю».
3. Отпустите кнопку после короткой фразы. Максимум 4 секунды; при нехватке непрерывного участка памяти плата уменьшает лимит до 3 или 2 секунд (см. Monitor). Запись дольше лимита автоматически заканчивается.
4. Сервер получает WAV с платы, распознаёт речь локально и возвращает текст на OLED. Длинный текст разбивается на страницы по четыре строки. Через некоторое время возвращаются эмоции. Последний результат также виден в браузере.

ПК должен работать и иметь доступ к IP платы. Дополнительные входящие порты и изменения брандмауэра не нужны: сервер по-прежнему слушает только 127.0.0.1, он сам опрашивает ESP32. Аудио хранится только в оперативной памяти и не отправляется в облако. Запись запускается только удержанием физической кнопки. Без сервера через 45 секунд плата покажет ошибку и освободит буфер.

Перенос на другой компьютер:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-stt.txt
```

Скачайте официальную модель https://alphacephei.com/vosk/models/vosk-model-small-ru-0.22.zip и распакуйте в `models/`, чтобы существовал каталог `models/vosk-model-small-ru-0.22/am`. Для другого пути Python задайте `MOCHI_PYTHON`. Модель и окружение не включаются в Git. Источник и лицензия модели: https://alphacephei.com/vosk/models.

Проверки: `node --test speech.test.js`. Проверяются локальный запуск настоящей модели, WAV, восстановление после некорректного WAV и повторная доставка текста. Распознавание короткой синтезированной русской фразы проверено отдельно; реальные звук, сеть и OLED требуют испытания на плате.

API: `GET /api/stt` — состояние и последняя расшифровка на ПК. Плата: `GET /api/stt/state`, `GET /api/stt/audio?id=...`, `POST /api/stt/result` (поля формы id/text). Повторная доставка результата не запускает новое распознавание.

Оптимизация задержки: сервер опрашивает плату каждые 150 мс, Vosk сохраняет модель и декодер между фразами и сбрасывает состояние записи через Reset. Первый запрос может быть медленнее последующих. В браузере и журнале сервера выводятся `downloadMs`, `recognizeMs`, `deliveryMs`, `totalMs`. Суммарное время отсчитывается после обнаружения готовой записи: оно не включает удержание кнопки, ожидание очередного опроса и физическую перерисовку OLED. Замер повторного распознавания одной синтетической фразы после прогрева сократился примерно с 820 до 150 мс; это не гарантия для новых фраз или других ПК. Аудио не обрезается и не сохраняется на диск.

Отдельный Node.js веб сервер для выбора эмоций ESP32. Компьютер остаётся подключённым к обычному домашнему Wi-Fi; ESP32 тоже подключается к этой сети. Node.js отправляет команды в API платы, а браузер открывает локальную страницу на компьютере.

## Первый запуск

1. В проекте `../mochi-oled` откройте `src/wifi_config.h`, впишите имя и пароль домашней сети Wi-Fi 2,4 ГГц и выполните **PlatformIO: Upload**. Текущие лица KITIOT рисуются кодом; **Upload Filesystem Image** не требуется.
2. После перезагрузки платы её IP-адрес появится на OLED на 10 секунд. Запишите его. Плата и ПК должны быть в одной локальной сети. ПК может работать на 5 ГГц, если роутер соединяет обе частоты в одну сеть.
3. Откройте эту папку `E:\Projects\ESP32\mochi-control-server` в отдельном окне VS Code. В терминале выполните `node server.js` или `npm start`. Нужен Node.js 18 или новее; пакеты устанавливать не требуется.
4. На ПК откройте `http://localhost:3000/`. Введите IP с OLED и нажмите **Сохранить IP**. Нажатие на кнопку эмоции отправит команду ESP32.

IP сохраняется локально в `config.json`; файл не содержит пароль Wi-Fi. Node.js сервер слушает только `127.0.0.1`, поэтому страница доступна на этом компьютере. Если после перезагрузки роутер выдаст плате новый IP, обновите его на странице. Для стабильного IP можно закрепить адрес платы в настройках DHCP роутера.

## API

Node.js: `GET /api/emotions`, `POST /api/emotion` с JSON `{"emotion":"happy"}`. Прошивка ESP32: `GET /api/emotions`, `POST /api/emotion` с полем формы `emotion=happy`.
